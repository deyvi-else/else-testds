# Test design system

## Purpose

This repo explores whether designers can deliver codified front-end assets (tokens, stylesheets, components, pages) directly from Figma designs.

The priority is fidelity, not speed. Every output must be an exact translation of the Figma design. If something in the design is ambiguous or can't be expressed with existing tokens, stop and ask rather than guessing.

## Source of truth

- Figma is the source of truth for all design decisions
- Figma file: https://www.figma.com/design/kDoLf0s6Vdeg8dS8cgi1ro/Test-design-system
- Only access the Figma file, pages or frames explicitly referenced in a request. Do not browse the wider workspace
- Never invent tokens, values or styles that don't exist in Figma

## Stack

- React + TypeScript
- CSS Modules for component styles
- CSS custom properties for tokens
- Style Dictionary (latest stable) to build tokens from DTCG JSON
- Storybook (Vite builder) for documentation and review

## Repo structure

```
tokens/                  DTCG JSON exported from Figma. Do not hand-edit
src/styles/tokens.css    Generated by Style Dictionary. Do not hand-edit
src/components/<Name>/   <Name>.tsx, <Name>.module.css, <Name>.stories.tsx
src/stories/foundations/ Token documentation pages, generated from tokens/
style-dictionary.config.mjs
```

## Token pipeline

1. Export Figma variables and styles to `tokens/*.json` (DTCG format)
2. Run `npm run tokens` to build `src/styles/tokens.css`
3. Token documentation in Storybook reads from `tokens/` so it never drifts

To change a token, change it in Figma and re-export. Never edit generated files directly.

## Token conventions

- **Prefix:** `--testds-` (the design system segment of the naming structure)
- **Naming:** Token names follow the segment order in the naming table below. Unused segments are omitted, not left blank. Segments are lowercase kebab-case, joined with hyphens
- **Collections:** Figma has two variable collections, `Primitives` and `Semantics`. Collection names are not part of token names; the token level is already in each variable's path (`testds/primitive/...`, `testds/semantic/...`)
- **Aliases:** Preserve references. A semantic token that points to a primitive outputs `var(--testds-...)`, never the resolved value
- **Colour with opacity:** Some semantic colours reference both a primitive colour and a primitive opacity. Output these with `color-mix()` so both references are preserved, e.g. `color-mix(in srgb, var(--testds-primitive-color-neutral-9) calc(var(--testds-primitive-opacity-2) * 100%), transparent)`
- **Units:**
  - Spacing in rem (16px base)
  - Border widths and radii in px
  - Opacity: Figma stores percentages (`5`). Output as decimals (`0.05`)
- **Modes:** The `Semantics` collection has two modes, light and dark. Light is the default and outputs on both :root and [data-theme="light"], so light sections can sit inside dark ones
- **Token names and groups:** A token name must never also be the start of another token's name (e.g. `secondary` and `secondary/hover`). DTCG JSON can't represent a value that is also a group. Use an explicit name for the default, such as `secondary/default`
- **Typography:** Defined by Figma text styles. Font family comes from a Figma string variable bound to each text style. Each text style outputs --testds-typography-<text style name>-<property> for font-family, font-size, font-weight, line-height and letter-spacing, with font-family as a reference to the primitive, e.g. var(--testds-primitive-font-family-sans). If a text style's font family isn't bound to a variable, flag it
  - Font size and line height in rem
  - Font weight as the exact numeric weight Figma renders, including variable weight axis values (e.g. 510, 590). Never map from the style name
  - Letter spacing: Figma stores a percentage of font size. Output in em (`2%` becomes `0.02em`)
  - Font is Inter, loaded from Google Fonts as a variable font covering the full weight range. Fallback stack: system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif
  - Components apply typography by referencing these properties in their CSS Modules
- **Effects:** None currently. If effect styles are added in Figma, include them in the export
- **One source for naming logic:** The code that turns Figma names into CSS names lives in one shared module, used by the build, the docs and the checks. Never duplicate it

### Naming table

Source: https://www.figma.com/design/kDoLf0s6Vdeg8dS8cgi1ro/Test-design-system?node-id=2-3075

If this table and the Figma frame disagree, the Figma frame wins. Flag the difference rather than choosing silently

Segment order:

`design system` > `token level` > `component family` > `component part` > `category` > `property` > `variant` > `state` > `scale`

| Segment | Purpose | Examples |
| --- | --- | --- |
| Design system | Namespace | `testds` |
| Token level | Tier | `primitive`, `semantic` |
| Component family | Component the token belongs to | Not yet used |
| Component part | Part of that component | Not yet used |
| Category | Type of value | `color`, `opacity`, `space`, `border` |
| Property | What it applies to | `background`, `border`, `text`, `icon`, `width`, `radius` |
| Variant | Hue or role | `neutral`, `primary`, `secondary`, `standard`, `subtle`, `strong`, `invisible` |
| State | Interaction state | `hover` |
| Scale | Step in a scale | `1` |

Examples:

| Token level | Segments used | CSS custom property |
| --- | --- | --- |
| Primitive | category, variant, scale | `--testds-primitive-color-neutral-1` |
| Primitive | category, scale | `--testds-primitive-opacity-1` |
| Primitive | category, scale | `--testds-primitive-space-1` |
| Primitive | category, property, scale | `--testds-primitive-border-width-1` |
| Semantic | category, property, variant | `--testds-semantic-color-background-primary` |
| Semantic | category, property, variant, state | `--testds-semantic-color-background-secondary-default` |
| Semantic | category, property, variant, state | `--testds-semantic-color-background-secondary-hover` |
| Semantic | category, property, variant | `--testds-semantic-color-text-subtle` |
| Semantic | category, property, variant | `--testds-semantic-color-icon-strong` |

## Component rules

- **Colour:** Components use semantic or component colour tokens only. Never use primitive colour or opacity tokens to build a colour in a component
- **Spacing, border radius and border width:** Components may use primitive tokens directly, as no semantic tokens exist for these yet. If semantic or component tokens are added later, use those instead
- **Opacity:** Primitive opacity tokens may be used for element opacity (the `opacity` property) only
- Never hard-code values (colours, sizes, spacing, radii, opacity) in component CSS
- If a design uses a value that doesn't match any token, flag it instead of hard-coding or rounding to the nearest token
- One folder per component with its TSX, CSS Module and story
- Props should map to Figma component properties and variants, using the same names where possible
- Build every state shown in Figma (hover, focus, disabled, etc.) and give each its own story
- Use semantic HTML and meet WCAG 2.2 AA
- **Focus states:** Use browser default focus styles for now. Never remove or override them (no `outline: none`), and make sure every interactive element is focusable with the keyboard. Custom focus styles may be added later with dedicated tokens
- Storybook documentation pages may hard-code layout-only values (swatch sizes, column widths, monospace font) where no token exists. Component CSS may not

## Definition of done

A component is done when:

- Its Storybook stories match the Figma frames in every variant and state
- Its CSS contains no hard-coded values, and no primitive colour tokens
- It builds without TypeScript or lint errors

## Working style

- Explain the reasoning behind any non-obvious decision
- When unsure how a design should translate, ask before building
- Keep a note of anything that didn't translate cleanly from Figma in `docs/learnings.md`
